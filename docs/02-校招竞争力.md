# 校招：这个项目怎么写才有竞争力

竞争力来自：是否解决了真实玩家问题，以及能不能用指标证明系统变好。只堆技术名词区分度不高。

## 技能点怎么估价

| 内容 | 作为技能点 | 写进项目经历时 |
|---|---|---|
| 加载、索引、检索、生成流水线 | 及格线 | 只写流水线没有区分度 |
| 父子块 / 查询路由 / 查询重写 | 能讲清为什么才有加分 | 要对应游戏文档和玩家问法 |
| 混合检索（向量 + BM25 + RRF） | 常见考点 | 最好有「只向量 vs 混合」的命中对比 |
| Graph RAG / Neo4j | 加分项，不是门槛 | 没有指标就不要写 |
| 评估（命中、忠实度、引用） | 比再加一个组件更值钱 | 简历上最该出现 |

## 三种完成度

- **能跑通**：对话能出字。只能证明环境配好了。
- **可演示（校招常用）**：自己的 Steam 语料，改过切分、元数据和路由，并有 30+ 题评测。能写优化前后对比。
- **更完整**：库存导入、热数据分流、失败归因；图谱只作为解决某一类检索失败的手段。

## 面试常问

- 为什么这样切分？结合游戏档案长度和召回精度。
- 混合检索好在哪？标签、游戏名、系列名这类关键词。
- 怎么知道变好了？固定问题集，而不是「感觉更准」。
- 热门榜为什么不走向量库？时效问题，静态档案解决不了。
- 为什么不上 Graph RAG？第一版没有证据表明关系检索是瓶颈。

经历条目建议写成：在 Steam 游戏语料上，把某某问法的命中或忠实度从 x 做到 y。
