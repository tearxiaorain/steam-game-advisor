# 产品范围：玩家顾问，不是排行榜

用户不是来看排行榜的，而是来问：「像《艾尔登法环》但更短、能和朋友开黑、电脑不太行、别太恐怖」。多约束、要解释，这是 RAG 比纯推荐模型合适的地方。

## 功能分流

| 玩家需求 | 更合适的实现 | 第一版 |
|---|---|---|
| 像某款游戏、某种手感/氛围 | RAG：简介、标签、评测语义检索 | 做 |
| 导入库存再推荐 | 库存 → 画像（标签/时长/未玩）+ 检索排序 | 做 |
| 某游戏怎么玩、适不适合我 | 父子块 RAG + 引用 | 做 |
| 近期热门、在线人数、折扣 | Steam API 或带时间戳的快照 | 后置，不要用旧文档冒充 |
| 开黑、配置、时长硬过滤 | 元数据过滤 + RAG 解释 | 能做简单版 |
| 攻略/机制问答 | 需要额外语料，范围容易失控 | 不做 |
| Graph RAG（系列/制作组） | 仅当相似检索失败且有对比数字 | 不做 |

## 建议扩展（按优先级）

**P0**

- 自然语言多约束搜索
- 可解释相似款
- 库存导入：今晚玩哪个

**P1**

- 热门/折扣快讯（结构化）
- 开黑助手
- 评测观点聚合（好评点/差评点）
- 配置与时长硬过滤

**P2**

- 攻略问答
- Graph RAG

## 数据约束

- 简介、标签、玩法说明：适合进向量库。
- 在线人数、热销、折扣：必须走 API 或带时间的快照。
- 库存：用 Steam Web API 已拥有游戏接口，不爬个人页。
- 商店数据：优先公开数据集或官方接口，避免大规模爬取。
